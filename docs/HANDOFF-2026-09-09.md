## What is carried as patches (not merged)

Three agents were stopped mid-work. Their commits were exported with
`git format-patch` into `docs/handoff/2026-09-09/*.patch`, each with a
`HANDOFF-*.md` written by the agent describing what is done, what is
half-done, and the next steps. They were NOT merged and NOT pushed as
branches, on purpose: Cloudflare builds and deploys the checkout Worker from
**every** pushed branch (`README.md`, "Two services deploy this site"), so a
pushed WIP branch with half-finished Worker code would go straight to
production.

To resume one:

```
git checkout claude/website-world-class-gaps-ox05mw
git am docs/handoff/2026-09-09/<name>.patch      # applies the agent's commits
# read the HANDOFF-<name>.md that arrives with it, finish, run the gates
```

If `git am` conflicts (the branch moved on), `git am --3way` or apply the
patch hunks by hand; the notes name every file and function.

## Rules that applied to all of this work

- **Owner rule.** Savanna edits the shop through Sveltia CMS at `/admin`.
  Anything she may need to change is a plain-language field in
  `admin/config.yml` with a hint, never a JSON or env edit; one-time
  technical setup goes in `docs/SETUP-GUIDE.md` / `workers/README.md`.
  `docs/EDITING-GUIDE.md` gets a walkthrough for every new field.
- **One branch, minimal pushes.** All work on this branch; push once when a
  batch is gated. Every push also deploys the Worker to production (see
  above), so never push a branch whose `workers/` is not release-ready.
- **Commit identity.** `git config user.email noreply@anthropic.com` and
  `user.name Claude` are set in this clone; commits made otherwise show as
  Unverified on GitHub and the stop hook rejects them.
- **Gates before a push.** `npm run lint`, `npm run format:check`,
  `npm run test:smoke`, `npm test`; for front-end or page changes also
  `node scripts/extended_qa_test.js`, `node scripts/puppeteer_tests.js`
  and `node scripts/a11y-check.js`; for Worker changes the relevant
  `scripts/worker-*.test.js` suites (all in `npm test`).
