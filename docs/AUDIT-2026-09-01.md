## Critical

### C-1 — Unauthenticated store-credit minting
`netlify/functions/redeem-points.js:139-212`, called from `assets/js/cart.js:519-540`.

`POST /.netlify/functions/redeem-points` with `{"points":500}` creates a real Stripe coupon and promotion code worth $25 and returns the code. There is no authentication, no server-side points ledger (the only balance is `localStorage["yl_loyalty_points"]`, and nothing in the codebase ever credits it), no rate limit, and CORS reflects any `Origin` (`:140-146`). The coupon is `duration: "forever"` with no `max_redemptions` on either the coupon (`:38-48`) or the promotion code (`:68-76`), so a single minted code is also unlimited-use. The same handler is an open mail relay from `orders@yallternativeliving.com` to any address (`:186-188`), which can exhaust the Resend quota that gift-card delivery depends on.

**Fix.** Remove the endpoint until a server-side ledger keyed to an authenticated customer exists. When rebuilt: `duration: "once"`, `max_redemptions: 1`, the same `ALLOWED_ORIGINS` allowlist the sibling functions use, per-IP rate limiting, and a real email validator.

### C-2 — Gift cards applied in the cart drawer are never debited
`workers/checkout.js:1002-1065`; `netlify/functions/fulfill-gift-card.js:268-311`, `:572`.

The Worker looks up the promotion code, mints a fresh ephemeral coupon for `min(total, balance)`, and attaches that via `discounts[0][coupon]`. The original promotion code is never deactivated or reduced. The webhook's `handleGiftCardRedemption` only finds a code through `session.discounts[0].promotion_code`, which Stripe leaves `null` when a coupon was applied, so it returns before any rollover. The Worker does write `gift_card_redeemed_code` / `gift_card_promo_id` / `gift_card_amount_applied_cents` into session metadata, but nothing reads them on the completed path. Two tabs can also double-spend concurrently. The balance checker keeps reporting the full balance afterwards. The hosted-checkout path (typing the code on Stripe's page) does debit correctly, so only the site's own UI is broken. The test that covers this (`scripts/backend-functions.test.js:2077-2081`) feeds the webhook the hosted-page shape, which the Worker never produces.

Chained with C-1: mint a free voucher, buy a gift card with it (gift cards are not excluded from session discounts), receive a transferable card that C-2 makes infinite.

**Fix.** In `handleGiftCardRedemption`, read the session metadata keys first and drive the rollover from them. Better, reserve at session creation (deactivate the source promo, mint the residual) and restore on `checkout.session.expired`. Add a regression test using `discounts: [{coupon, promotion_code: null}]`. Refuse gift-card pre-application on sessions that contain `yallternative-gift-card`.

### C-3 — Service worker cross-serves gift-card balances
`sw.js:116-183`; consumers `assets/js/cart.js:499-517`, `assets/js/gift-card.js:63-100`.

The fetch handler strips the query string from the cache key and applies stale-while-revalidate to every same-origin GET that is not a navigation or `.js`/`.css`. `GET /.netlify/functions/gift-card-balance?code=…` therefore caches under a code-less key: after one valid lookup on a device, every later lookup of any code, valid or not, returns the first card's code, balance and initial amount. The drawer stores that whole object and sends its `code` to checkout, so shopper B spends shopper A's card.

**Fix.** Return early for `/.netlify/` and `/api/` before the cache-key logic; send `Cache-Control: no-store` from `gift-card-balance.js`.

### C-4 — CMS content becomes CSP-approved script
`scripts/build-site-data.js:2268-2277` (Tawk IDs into a JS string literal in a hashed inline script on 11 pages), `:1103-1126` and `:1200-1201` (JSON-LD via `JSON.stringify` without `<` escaping, so `</script>` in a product name, blurb or FAQ breaks out), `:2181-2258` (logo path, Umami and Gift Up IDs into attributes unescaped); `scripts/build-security-headers.js:119-136`.

The header generator re-hashes whatever inline scripts the freshly built HTML contains on every deploy, so injected script is automatically allowlisted. Its comment claims it verifies scripts are byte-identical across pages; it does not. All three payloads were reproduced in a scratch copy and their hashes landed in the emitted CSP. Any CMS editor, or anyone holding the CMS's GitHub token, gets script execution on the shop and checkout pages with no CSP violation.

**Fix.** Compare the computed hash set against a committed baseline and fail the build on any new hash. JSON-encode values into JS context (or move the IDs to `data-` attributes read by `main.js`); escape `<` as `<` in JSON-LD (the CMS auth worker already does this at `cms-auth/sveltia-auth.js:94-96`); route the attribute sinks through the file's own `escapeHtml`; add `pattern:` validators in `admin/config.yml`.

### C-5 — `404.html` is broken anywhere but the root
`404.html:25,42-43,67-77,108-109,256-261`.

Netlify serves `404.html` at the requested URL, and the file uses 22 document-relative paths for its CSS, six JS bundles, manifest, logo and nav links. A request for `/products/anything` renders an unstyled, scriptless page whose every escape route is another 404. The footer in the same file already uses root-absolute links. `main.js:8084` has the same bug for `translator.js`, so Google Translate never initialises on product pages.

**Fix.** Root-absolute paths in `404.html` and for the translator load.

## High

### Money and orders

- **H-1 Near-miss variant labels skip price deltas and sold-out checks.** `workers/checkout.js:585-596,807-812`. An unknown label is silently accepted: `"24 oz "` (trailing space) on `lavender-soak` charges $10 for the $18 jar, and the raw client string is printed in the Stripe line item so the merchant ships the larger size. Exposed deltas: bath-tea 3-Pack +$12, lavender/backroad soak 24 oz +$8, cleansing-spray 4 oz +$8, shea-butter 8 oz +$5, hand-scrub 4 oz +$4. Sold-out `tank-top` size S is purchasable as `"S "`. Fix: require an exact (whitespace/case-normalised) match, return null otherwise, and build the line name from the catalog label.
- **H-2 Any `pickupMarket` string zeroes shipping.** `workers/checkout.js:877-884,943-963`; `assets/js/cart.js:2132-2141`. The label is only validated when Stripe Tax is on (it is off). `shop.html?pickup_market=x` or ticking pickup then entering a shipping address gets $10 shipping free. Fix: validate against `events.json` unconditionally; do not collect a shipping address when pickup is honoured.
- **H-3 Cart total omits shipping and tax.** `assets/js/cart.js:1484-1540,1564`. The drawer's "Total Due" line has no shipping line; the Worker adds $10 under $40 and caps the gift card on total plus shipping. A $30 cart with a $50 card shows $0.00 and is charged about $10 plus tax. Fix: render a shipping line from the same threshold the milestone meter uses; relabel as an estimate before tax.
- **H-4 Coming-soon and stock are not enforced server-side.** `workers/checkout.js:791-805`. Five `comingSoon` products and any quantity up to 99 regardless of `stock` can be paid for. Fix: reject `comingSoon`/`inStock:false`, clamp to `entry.stock`.
- **H-5 Refund balance restoration is dead, and would double-restore if wired.** `netlify/functions/fulfill-gift-card.js:429-531,552-560`. It reads charge metadata the Worker never sets (no `payment_intent_data[metadata]`), every deploy doc says to subscribe only to `checkout.session.completed`, it ignores the refunded amount, and it handles both `charge.refunded` and `refund.created` with different idempotency keys. Fix: look up the session by payment intent, restore `min(applied, refunded)`, handle one event, key on the refund id.
- **H-6 Order status fabricates a confirmed order for any input.** `assets/js/main.js:3146-3391,5651-5800`; `order-status.html`. No request is ever made; any email, `cs_…` or `YL-…` string renders "Order Confirmed, payment processed via Stripe", a hardcoded Frankincense Salve + Miracle Balm order, and a printable packing slip. The "security verification" field only checks non-emptiness and `cs_` skips it; `?email=` reflects PII into the input. The reorder button adds the fake items to the real cart. The CMS toggle that claims to disable it is read by nothing. Fix: back it with a real Stripe lookup or ship only the existing "email us" fallback.
- **H-7 Thank-you page renders a printable gift certificate from URL parameters.** `assets/js/thank-you.js:47-83,119-165`. `?gift_code=…&amount=500&sender=…` shows a $500 certificate on the real domain; the Worker's success URL never carries these parameters, so real purchases never trigger it. `?session_id=x&amount=999999` also fires the Purchase analytics event and wipes the visitor's cart, and a bare visit shows a hardcoded $25.00 order. Fix: drive from a verified session lookup or delete.
- **H-8 Bulk gift-card orders fail at Stripe.** `workers/checkout.js:823-846`. Four metadata keys are written per gift-card unit; Stripe caps 50 keys, so quantity 13 with a message (26 with only a recipient) makes session creation fail with the generic "Checkout failed". Fix: per-line keys plus quantity, expanded in the webhook.
- **H-9 A redemption failure blocks gift-card creation for the same order.** `netlify/functions/fulfill-gift-card.js:566-574,762-766`. Both run in one `try`; a rollover error 500s the whole webhook, Stripe retries forever, and purchased codes are never emailed. `RESEND_API_KEY` also silently defaults to `"re_test"` (`:26-29`), producing the same loop after a charge. Fix: isolate the redemption in its own try/catch; fail at load when the key is missing.
- **H-10 "Apply to Cart Now" does nothing, then deletes the card.** `assets/js/gift-card.js:87-105`; `assets/js/cart.js:860-914,1019-1046`. The balance checker writes `localStorage` that the cart reads only at init; the next `save()` removes the key. Fix: expose `YLCart.applyGiftCard()`.
- **H-11 Actionable checkout errors are hidden.** `assets/js/cart.js:1901-1921`. The Worker's curated 400 messages ("Product not found: …") are replaced with "try again in a moment", so a stale cart fails forever with no clue and no remove affordance. Fix: show 400 messages; reconcile the cart against the catalog on load.
- **H-12 Cart drawer clips the Checkout button on short viewports.** `assets/css/cart.css:20-36,138-142,309-314`. The footer has no max-height or overflow and `cart.css` has no viewport breakpoints; with the gift and pickup blocks expanded the footer exceeds the drawer and the Checkout button is unreachable on an iPhone SE-class screen. Fix: `max-height`/`overflow-y: auto` on the footer, `min-height: 0` on the items list.

## Data integrity and generated-file drift

**The generator is idempotent.** A full rebuild in a scratch copy rewrote 7 data files, 13 pages, 19 PDPs, sitemap, feed, robots, llms and `sw.js`, and the only differences were the two wall-clock stamps (H-20). Every one of the 118 `<!--YL:…-->` markers already holds what the build emits. `products.json` passes a full schema check (19 products, 7 bundles, 46/46 images on disk with AVIF and WebP variants, all `pairsWith` and bundle references valid). The problems are in the inputs and in a small number of escaping gaps.

### High
- **Etsy rating sync is silently lost.** `scripts/apply-etsy-snapshot.js:62,195-209,283` reads and writes `assets/js/products-data.js`, which has been generated from `products.json` since the source-of-truth flip; the very next build overwrites it. Proven: a synced rating went in, the rebuild wiped it. Every Etsy sync since the flip has been a no-op. Fix: write to `products.json`.
- **`sitemap.xml` is not well-formed XML.** `scripts/build-site-data.js:1773` emits a comment containing `--`, which `xmllint` rejects ("Double hyphen within comment"). Strict consumers drop the whole file.
- **Fabricated ratings and reviews on unreleased products.** `sugar-scrub` and `whipped-body-butter` carry `rating {5, 1}` with no Etsy listing, no snapshot entry and no site review, and the build emits `aggregateRating` for both alongside `PreOrder`. `site-reviews.json` publishes three "verified buyer" reviews for `cleansing-spray`, `bath-tea` and `porch-sweep-spray`, all `comingSoon`. Structured-data manual-action risk. Fix: remove the two unbacked ratings and assert at build time that a product `rating` is backed by at least one real source: an Etsy listing present in the snapshot, or at least one review for that product in `site-reviews.json` (reviews submitted through the website count). Reviews of products that have never shipped must not be marked verified buyers.
- **Unescaped image paths in four attribute sinks.** `build-site-data.js:2787,2816,3183` (`<img src>`) and `:3113,3128` (`og:image`, `twitter:image`). A poisoned `image` path on one product lands on every PDP that pairs with it (four pages in the proof). The sticky bar and `injectPageCopy` do escape or strip; these were missed. (Part of C-4's fix.)
- **Coming-soon and stock unenforced server-side** (duplicate of H-4; reproduced here against the live catalogue, and `llms-full.txt:17-31` advertises the endpoint to purchasing agents as always re-deriving from `products.json`).

### Medium
- **Gift-card variant labels contradict the checkout protocol.** `products.json` declares `$10/$25/$50/$100/$200`; the Worker parses only `Preset $NN`, so `"$200"` resolves to the $10 floor. Nothing sends those labels today (the page emits `Preset $NN`), but they are published in `products-data.js` and `search-data.js` and would produce a $10 charge for a $200 card from a stale cart or a future picker. Relabel or delete.
- **`events.json` still lists three finished August markets as upcoming.** The build archives them in memory, but `workers/checkout.js:207` fetches the raw file, so a pickup label for a market weeks past still resolves for tax sourcing. Archived events also lose `id` and `zip` (`build-site-data.js:500-509`), so three of eight search results link to `events.html#undefined`.
- **Journal is "off" but published.** `enableJournal: false` correctly blanks the nav, `noindex`es the page and omits it from `sitemap.xml` and `llms.txt`, yet both posts ship with full body text in `search-data.js`, `journal-data.js` and `feed.xml`, and `sw.js` precaches the page. Both posts' `featuredProductId` (`magnesium-body-butter`, `pine-tar-salve`) reference products that do not exist; the build validates `pairsWith` and bundle ids but not this relation.
- **Config-injection text and attribute sinks unescaped.** `build-site-data.js:1295,1650,2183,2189,2214,2248`: `birthdayTitle`, `birthdaySubtext`, `loyaltyPointsName` and similar go into HTML text raw (`<img onerror>` in a birthday title lands on `thank-you.html`); logo path, Umami and Gift Up IDs, and event `datetime` go into attributes raw. (Part of C-4's fix.)
- **`shop.html` JSON-LD availability is derived from the image filename** (`build-site-data.js:975-997`, `placeholder` in the path means `PreOrder`), while PDP JSON-LD reads the real flags. Adding a photo to a coming-soon product makes the shop page advertise `InStock`.
- **Bundles containing sized products carry no size.** Five of seven bundles include `unisex-tshirt` or `frankincense-salve`; the bundle path skips variants entirely, so the Stripe line has no size and the shop must guess.
- **Three volume-pricing implementations.** `workers/checkout.js` and `assets/js/cart.js` agree byte-for-byte; `main.js`'s badge logic is looser (no text match, no price comparison), so a future variantless salve or a salve under $14.99 would be badged "2+ for $14.99 ea" while cart and checkout refuse it, and the frankincense badge stays visible on the 1oz selection. Today all three resolve to `frankincense-salve@2oz` and `sleep-salve`.

### Low
- `escapeHtml` passes XML-illegal control characters into `feed.xml` (verified parser error on `U+000B`).
- `assets/img/protection-keychain-alt1-800.{avif,webp}` are orphan variants referenced by nothing.
- Variant label convention is inconsistent (`2oz` vs `2 oz`); whitespace normalisation hides it for now.
- `llms.txt` shows no availability, so five coming-soon products read as buyable there; it also prints an Etsy link for products with no listing.
- Etsy-to-site price drift on eight products (for example frankincense $16 vs $19.99) is reported on every sync run.
- Gift-card PDP JSON-LD declares a $10 shipping rate and mail returns for a digital product.
- `cart.js:1376` falls back to a "Landrum SC Farmers Market" pickup label that matches no event, so once the October faire passes, pickup tax sourcing silently falls back to the buyer's address.
- `search-data.js` (51.9 KB) duplicates about 35 KB of `products-data.js`; both load on every page.
- Two script headers (`apply-etsy-snapshot.js:6`, `optimize-images.js:27`) still name `products-data.js` as the source of truth.
